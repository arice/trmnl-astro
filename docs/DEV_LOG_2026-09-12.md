## Session 1 — Fix stale-data trap in the local test loop

**What was asked:** Review the codebase and walk through how to test a new display design.
That review turned up a bug in the test path, and the fix was approved.

**What was built:**
- Rewrote `test_chart.py`'s position loading with two independent staleness guards:
  - mtime-based source selection — past `_STALE_AFTER` (2h), fetch from GitHub Pages
    instead of trusting the committed local file
  - `_sun_lon_now()` cross-check — computes the Sun's true ecliptic longitude and warns
    when the loaded data disagrees, reporting the discrepancy in days
- Restructured the module-level if/elif chain into `load_positions()` with an explicit
  four-way preference order, moved mid-file imports to the top, renamed `MOCK_POSITIONS`
  to `POSITIONS` (it is usually live data, not a mock)
- Created `.claude/LEARNINGS.md`

**The bug:** `test_chart.py` only fell back to the Pages URL when `docs/last_positions.json`
was *missing* — but CI commits that file, so it always exists locally and always won. The
local copy was 186 days old. Charts rendered from it put the Sun in Pisces while the live
sky had it in Virgo, a clean 180° error. The footer timestamp comes from `datetime.now()`
rather than the data's own time, so the wrong render looked perfectly current. Every design
judgment made off a local render since March was made against the wrong sky.

**Decisions made:**
- Two guards rather than one. mtime alone is defeated by `touch`, a fresh clone, or a
  checkout of an old commit — all of which produce a recent mtime over old content. The
  sun check validates the *data*, so it holds regardless of how the file got there.
- Used the low-precision solar formula from the Astronomical Almanac (~15 lines, no new
  dependency) over pulling in an ephemeris library. Verified against the live API:
  computed 169.51° vs API 169.50°.
- Threshold of 1.5° (~1.5 days) for the warning — wide enough that clock skew or a
  slow CI run never trips it, tight enough to catch being a day off.
- `--fallback` suppresses the sun warning, since choosing the collision test case is
  deliberate and its data is intentionally not today's.

## Session 2 — New wheel design, shipped to production

**What was asked:** Make the chart glanceable — bigger glyphs, smaller wheel. That turned
into a long iteration on placement, then a font investigation, then promotion to production.

**What was built:**
- Rewrote the wheel renderer. Glyphs are 40px on a 2/3-size wheel (`outer_r` 92), each with
  its degree beside it at half size, and ASC/MC drawn the same way.
- Replaced tangential collision resolution with **radial-first placement**: a crowded glyph is
  pushed outward along its own ray, which costs depth but keeps the angle exact. Sideways
  movement is a last resort and is bounded so it can never reorder two bodies.
- Symbols are now **Astronomicon** (OFL), vendored at `fonts/`. Glyph tables in `base.py`.
- Split `SYMBOL_FONT` into `GLYPH_FONT` / `TEXT_FONT`.
- Moon phase is **drawn** (two arcs) rather than typeset — no font that carries the zodiac has
  the phase emoji, so it had been rendering as a tofu box.
- Fixed the legend: header was cropped off the top edge, figures rebalanced against glyphs.
- Fixed the workflow's font step (see below). Promoted `dev.py` to `production.py`.

**Measured over 3000 synthetic skies, a third with forced stelliums:**
75.5% of glyphs at their exactly-correct angle, mean drift 2.5°, p95 15°, and zero ordering
violations, zero label overlaps, zero labels outside the panel. 13ms per render.

**Decisions made:**
- **Order is a harder constraint than accuracy.** A glyph a few degrees off is a small error;
  a glyph drawn *before* one it comes after is a different chart. Enforced by cutting the
  cycle at its widest gap and requiring placed angles to stay monotonic. Cost ~0.7° of mean
  drift and is worth far more than that.
- **Radial over tangential.** `production.py` already did radial stacking before this session;
  the tangential solver I replaced it with was a regression I had to be told about.
- **Vendored the font** rather than fetching it. The build had been fetching one over HTTP.
- **Degrees to the right, not below.** Below measures better (87.7% vs 75.5% exact) because
  the panel has more vertical than horizontal room, but side-by-side reads better. Chosen
  deliberately; `DEGREE_PLACEMENT` switches it.

**What could have gone better:**
- Three separate times the *audit* was wrong rather than the renderer: it measured Astronomicon
  glyphs with a text font, it counted ring glyphs as overlapping when arc spacing already
  cleared them, and it understood only `text-anchor="middle"` so every `start`/`end` box landed
  in the wrong place — reporting 1500 overlaps across 1500 skies. A validation tool that
  silently mismodels what it checks is worse than none. Each time the giveaway was an
  implausible number, not a wrong picture.
- I optimised angular drift while letting labels drift outward to r=224 against an 87px rim.
  The metric improved and the chart got worse, and the user had to point it out. The metric
  ignored radius entirely.
- The font investigation should have come first. Several rounds of tuning glyph box constants
  were done against Apple Symbols metrics while CI was rendering in DejaVu, so local numbers
  never described what shipped.
